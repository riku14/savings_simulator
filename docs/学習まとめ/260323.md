### イベントの型について
onChange関数でよく目にする以下の `e: React.ChangeEvent<HTMLInputElement>` はイベントeの型を指定している。
- 今回は`<input>`タグでのイベントなのでHTMLInputElementだが`<select>`の場合は`<HTMLSelectElement>`にジェネリクスを設定する
- `e.target.value`で受け取った値は`string`型になっている。
```js
function handleChange(e: React.ChangeEvent<HTMLInputElement>)
```

### 型定義について
id等の型を定義する際にフロントではoptional型として`id?: number`とすることで計算ロジックでの必須を回避できる

### Reactのprevについて
useStateでset関数で値を更新している場合に起こりうる以下の事象
1. useStateとして`[state, setState]`があるとする
2. このstateをhandleChange関数でsetStateを使用して更新している
3. ボタン連打した場合に最新の情報ではない古いstateの値で処理してしまい意図しない結果になる。
**なぜ起こるのか** → Reactのset関数などはまとめて処理する場合がある（非同期、バッチ）そのため連打すると更新前の値が使用される可能性がある
上記を防ぐために以下の様にする。こうすることでReactが勝手に`prev`には最新の直前の値を引数として渡すので上記の問題を防げる
```js
setState((prev) => ...)
```
